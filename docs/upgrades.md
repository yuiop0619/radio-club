# 互动版升级与运行

## 已实现

- 吧台：入座、菜单分类、数量调整、拖入纸单、确认与修改订单、逐份上菜、点击品尝；草稿和上菜进度刷新可恢复，支持多标签页串行保存与减少动态效果。
- 2006：五章复古桌面档案、阅读进度、收藏、浏览器前进后退、照片放大、窗口控制、用户主动开启的本地合成调频音。原文保留。
- 数据：默认本机保存；可下载 JSON 备份，主动勾选后手动上传、预览和恢复服务器快照。恢复前保留本机备份。故事原文默认排除，不做后台自动同步。
- 后端：身份会话、恢复码、私有快照版本冲突保护、公开纸条、举报审核、管理员菜单文案与章节附注编辑。
- 素材：32 张原始图片清理角落水印，重新生成响应式资源；生成式修补可能带来局部细节变化。

## 技术选型与边界

Vue 3 + TypeScript + Pinia + Vite 管理新增交互，旧 JavaScript 页面逐步迁移。Node 后端仍是 JavaScript；这是 TS/JS 为主的渐进升级，并非全部页面重写。2.5D 图片分层和浏览器动画已经能表达选菜、传单、上菜，目前没有引入重型三维模型。

文件数据库是单进程、小规模部署方案，不允许多个实例同时写同一目录。公网规模化之前应替换为 PostgreSQL 等数据库，加入备份恢复演练、过期会话清理和集中监控。当前没有支付、邮箱登录或完整 CMS；管理端支持指定文本字段，不允许上传任意 HTML。

## 本机运行

Node.js 22.12+，执行 `npm ci`、`npm start`，打开 http://127.0.0.1:8080 。服务只监听本机。`npm run dev` 提供前端热更新，需同时保持 8080 后端运行。

本机服务器与浏览器存储分离，服务器默认数据在 `.data/radio.json`，已排除出 Git，也不能经静态地址下载。删除浏览器数据不会删除已上传的服务器快照。持有恢复码者可以恢复身份；重新生成恢复码会废止旧码。

## Node 公网部署准备

1. 在服务器安装依赖并执行 `npm run build`，以单实例运行 `node tools/server.cjs`，使用进程管理器保持运行。
2. 通过 HTTPS 反向代理转发至本机端口；设置 `RC_ORIGIN=https://你的域名`，不要带结尾斜杠。代理须保留同站请求的 Origin。`PORT` 可更改监听端口。
3. 设置 `RC_DATA_DIR` 指向持久磁盘上的绝对路径，不能放在临时部署目录。默认 `.data` 不适合无持久卷的平台。
4. 停止服务后复制整个数据目录到受保护的备份位置；恢复时停止服务、替换目录，再启动并检查记录。备份包含私密记录，应限制访问。
5. 先在“保存与同步”连接取得自己的身份 ID，再设置服务端 `RC_ADMIN_UIDS` 为该 ID；多个 ID 用英文逗号分隔。重启后重新连接，可看到举报与内容编辑。管理员授权不能放到前端配置。
6. 验收两个独立浏览器的公开留言、私有记录隔离、恢复码、版本冲突和举报处理，再开放访问。

这些环境变量由部署平台或进程环境提供，项目不会自动读取 `.env`。当前未配置公网域名或云账号，也没有声称已完成公网部署。

## CloudBase 可选路线

原有云函数已扩展私有快照、审核和内容接口，部署见 cloud-deployment.md。恢复码端点属于 Node 方案；CloudBase 应使用其登录方式。静态 CloudBase 模式下，公开菜单附注暂使用仓库默认内容（公开读取目前走同站 `/api/content`），不应宣称与 Node 方案完全等价。

## 后续顺序

优先部署持久化后端并验证真实双设备，然后补账号体系与自动备份；再逐页迁移旧 JS、增加可替换的人物动作素材。只有需要自由旋转视角和摆放物体时，再加入 Blender / Three.js 建模流程。
